- A global settings document does not overwrite old personal settings.
- Captures require each selected service, not a numeric count. Four YouTube URLs
  cannot substitute for Lovable/Notion/NordVPN. Incomplete batches save nothing.

  Legacy authenticated sync cannot save disabled-service URLs either.

  export; switching it off preserves its history.

  regeneration with a new key. Active v6 scripts stay unchanged on this update.
- Delayed copy/regenerate requests recheck account and revocation state before
  returning code. Revocation during generation cannot reactivate a stale key.
- Explicit generation converges on one slot; stale record writes cannot replace
  newer keys. Manual revocation atomically advances capture version and saves the
  reason without ending the current login session.
- Encryption recovery/context binding, wrong/missing key behavior, script slot
  concurrency and compare-and-replace guards. Upgrade cannot resurrect a revoked
  script or overwrite a replacement/newer-password version.
- User isolation, limited capture-key permissions, wrong-page rejection, manual
  import ownership, password changes/resets, disable and self/admin revocation.
- New/duplicate/mixed/missing outcomes; idempotent batch retries retain counts.
  Storage acknowledgement precedes success. Exported/history rows remain intact.
- Short passwords, invalid passwords, sessions, export retention and IST filenames.

Limits:
- Storage tests use MemoryRepository and a MongoDB query/update contract double,
  not an actual Atlas instance or native MongoDB engine. No deployment to the
  user's Railway/GitHub service was performed.
- The actual LinkedIn DOM and browser policies were not live-tested. Fake source
  anchors/reward codes were used; no reward destination was visited or redeemed.
- Headspace's real LinkedIn perk sample was not provided. Tests cover recognized
  official redemption/checkout URL shapes; a different format may need a rule.
- Main-document a[href] only; no iframe/shadow-root/click-only adapter.
- Local timing does not guarantee remote Railway/MongoDB latency. Confirmation
  needs internet/backend availability; there is no offline queue. Isolation or
  blocking can require a save window/manual handoff and additional time.
- Scripts remain private reusable code, not automatic post-refresh installations.
