NEW INSTALLATION
1. Create a dedicated MongoDB database/user with readWrite permission. Allow
   Railway's outbound connection in Atlas Network Access.
2. Upload the project contents to your GitHub repository and deploy on Railway
   using the settings above. Generate a public HTTPS domain.
3. Add the six variables from RAILWAY_ENV_EXAMPLE.txt with your actual values:
   MONGODB_URI, MONGODB_DB, ADMIN_USERNAME, ADMIN_PASSWORD, PUBLIC_URL,
   SCRIPT_ENCRYPTION_KEY.
4. PUBLIC_URL must include https:// and contain only your public origin:
   https://YOUR_SERVICE.up.railway.app (no admin path).
5. For initial setup only, open GENERATE_SCRIPT_ENCRYPTION_KEY.html locally and
   generate/copy one random 64-hex value to SCRIPT_ENCRYPTION_KEY. Keep the exact
   same value on future deploys; store a private backup outside GitHub.
   The offline generator contains no prefilled secret and sends no requests.
6. Redeploy, log in as initial admin, configure capture settings and create users.
   An existing admin's password is not reset by changing Railway ADMIN_PASSWORD.
7. Each user clicks Generate script, copies it and runs it in the source Console.
The panel/history still load without a valid script secret, but script copying
shows a setup error. A different secret cannot decrypt previously saved scripts.
Keep Railway available (disable service sleeping for prompt responses), monitor
storage and keep independent database backups. No Windows setup is needed.
