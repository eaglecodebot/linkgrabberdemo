LINK GRABBER WEB v5 — DEPLOYMENT
================================

EXISTING SERVICE: ADD ONE VARIABLE
1. Open GENERATE_SCRIPT_ENCRYPTION_KEY.html from the extracted ZIP in a browser.
   Click Generate initial setup value once and Copy variable line.
2. Add it in Railway -> your service -> Variables -> Raw Editor:
     SCRIPT_ENCRYPTION_KEY=<the generated 64-character random hexadecimal value>
3. Keep this same private value for future deploys. Back it up outside GitHub.
   It encrypts/retrieves the permanent scripts stored in MongoDB. If the variable
   already exists, KEEP it instead of generating a new one.
4. Keep all existing MONGODB_URI, MONGODB_DB, ADMIN_USERNAME, ADMIN_PASSWORD and
   PUBLIC_URL values. Keep the same MongoDB database, accounts and snapshots.
5. Upload the CONTENTS of Link_Grabber_Web to your GitHub repository root.
6. Let Railway rebuild with cloud/Dockerfile and node cloud/server.mjs.
   Service root remains /. Root npm start also starts the hosted backend.
7. Refresh your public Railway panel with Ctrl+F5. Log in, save page settings,
   then Copy my script once to obtain your permanent v5 script.
Old v4 scripts are not automatically converted to permanent ones. Users copy v5
once after upgrade. No database reset, extra PC software or password reset needed.
A permanent_scripts collection/hash index initializes automatically. Expiry of
old v4 keys remains in capture_keys; the new permanent records have no TTL.
The panel/history can run without the new secret, but copying scripts gives a
clear setup error. A wrong replacement secret cannot decrypt old saved scripts.

NEW INSTALLATION
1. Create an Atlas database/user with readWrite permission for the dedicated DB.
2. Allow your Railway outbound connection through Atlas Network Access.
3. Upload project contents to a private GitHub repo and deploy on Railway.
4. Use root /, cloud/Dockerfile, and node cloud/server.mjs.
5. Generate a public HTTPS domain and configure all six values from
   RAILWAY_ENV_EXAMPLE.txt with real values, including the new script secret.
6. PUBLIC_URL must be the exact origin with https://, without a path.
7. Railway supplies PORT; the server binds to 0.0.0.0. Health: /health.
8. Redeploy, log in as initial admin and create ordinary panel users.
The initial admin is created only when absent. Changing ADMIN_PASSWORD in Railway
later does not change the existing administrator password stored in MongoDB.
Keep the service funded and disable Serverless/App Sleeping for prompt responses.
Keep independent MongoDB backups and monitor storage.

USERS
Public panel -> log in -> main-page settings -> Copy my script -> paste/run in
source-page Console -> check Saving to: username and wait for the actual result.
No Windows program, extension, PowerShell, BAT, local panel or PC Node install.
