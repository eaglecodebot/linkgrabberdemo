EXTENSION CODE UPDATES AND WORKFLOW URL SETTINGS
Link Grabber Web v6.5.0 / Private Workflow Runner v1.10.0
30 October 2026 (IST)

ADMIN: SET WORKFLOW URLS AND OPTIONAL TRIAL ALTERNATES
1. Deploy this full project to Railway and hard-refresh your panel (Ctrl+F5).
2. Log in as admin. Find Extension workflow URLs - all users.
3. Enter:
   Trial - primary starting URL: startUrl
   Trial - alternate starting URLs: trialAlternateUrls (one per line; optional)
   Cancel & Refund - URL 1: step2StartUrl
   Cancel & Refund - URL 2: step2SecondUrl
4. Click Save workflow URLs.
5. Users download/install their personalized v1.10.0 extension once.

New ZIPs contain these URLs. Installed v1.10+ extensions refresh them when starting
Trial or Cancel & Refund, so URL-only changes need no new extension download.
A workflow already running keeps its initial URL snapshot until it finishes.
Trial alternates are exact entry pages, not a sequence of navigation actions.
An open primary/alternate tab is reused. Otherwise only the primary is opened.
A listed redirect still needs the first captured control to be uniquely ready.
Up to 50 full HTTP(S) alternate URLs; no credentials, spaces or wildcards.
Empty lines/duplicates/the exact primary are removed. Clear the list to disable
alternates. Old local or historical lists cannot override current admin values.
Cancel & Refund continues to use only its own two URLs.
The alternate list is hidden in personalized extension Settings. Users cannot
override any of these URL values there. Other
preferences remain local. Blank URLs leave the respective workflow unconfigured.
Capture URL/services are configured separately in the existing capture form.
The managed workflow URL endpoint still works if capture services are paused.
A revoked capture connection must be regenerated and downloaded again first.

ADMIN: PUBLISH UPDATED EXTENSION FILES
The shared integrated extension lives here in your GitHub project:
  cloud/extension-template/

1. Update its runtime files (background.js, popup.js, engine.js, workflow.json,
   content.js, options files, styles or any other changed runtime assets).
   Keep the Grab Links integration, grabber.js/grabber-page.js and the personal
   connection loading code. Do not replace this whole folder with an older,
   unintegrated Trial/Cancel-only extension. Supply the newer extension for merging
   if its source changes are not already integrated with Grab Links.
2. Increase the version in cloud/extension-template/manifest.json, for example:
   "version": "1.10.1"
   Use a Chrome-compatible numeric extension version.
3. Upload/commit the changed files to GitHub and redeploy Railway.
4. No extra env variable, database reset or script regeneration is required.

The server hashes the integrated runtime files to identify each release. A code
change is detected even if the version number was accidentally left unchanged;
version bumps are recommended so users can recognize the update. Text guides,
tests and personal connection JSON do not change the shared runtime release ID.
Nested runtime folders such as icons/ are included in downloads and release IDs.
The decoder is generated from src/decode.mjs so console/extension matching stays
consistent. Update the server decoder when adding/changing reward link formats.
Do not include private capture keys in your source template.

WHAT USERS SEE
- One automatic panel notification per account for each release, recorded in
  MongoDB. Refreshing/reopening the panel does not replay the notification.
- An update card with Update & download extension, beside the console script.
- The ZIP contains the latest shared files, the admin URLs and that signed-in
  account's existing permanent capture connection. Viewing another user's history
  as admin does not change the account used in an extension download.
- The update card clears after the browser receives the ZIP and confirms the
  download. Preparing a ZIP or a failed download does not clear it.
- Download my extension stays available for manual redownloads later.
- Notification/download records are separate from link history and account
  authentication. They survive another PC or a browser reset because they are
  stored in MongoDB; the download button remains available after a reset.

USER: APPLY A DOWNLOADED UPDATE
1. Stop an active workflow and finish any pending capture.
2. Click Update & download extension in your panel.
3. Extract the ZIP over the SAME permanent extension folder used when you chose
   Load unpacked. Allow the updated files to replace the old files.
4. Open chrome://extensions and press Reload for Private Workflow Runner.
5. Refresh an already-open source page before starting the next task.

This is a download-and-reload update. The website cannot silently overwrite the
installed extension folder. Download tracking does not claim that every PC or
browser profile has actually installed the files. Reload each installed profile
that uses the folder. Keeping the same installed folder retains local timing and
pincode preferences; all workflow URLs remain managed by the admin.

Keep your ZIP private because it contains your personal capture key.
